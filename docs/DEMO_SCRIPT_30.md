# Complete end-to-end NOVATECH workflow — 30-minute script

The six-person relay: company, appetite, ransomware response through all seven gates, the report — and the power-off decided by the device owner.

Generated from the Presenter Mode scene library (`npm run script:export`). The live console shows the same text privately; the projector never does.

## Before you start

- Laptop on mains power, projector as an **extended** display (not mirrored).
- Use **Microsoft Edge**: its free “Natural” voices (Neerja, Prabhat — Indian English) are the smoothest. In Voice & settings, **Test NOVA** should show the voice as *natural*.
- Open Presenter Mode → choose the show and length → **Open audience window + console**. Drag the audience window to the projector and click **Start the projector** on it once: full screen, sound and NOVA’s voice in one click (browsers need one click in every window).
- On the console, press **Test projector sound**. Starting the presentation switches NOVA’s voice on (unless narration is set to Off).
- Nobody logs in. The app switches to each person’s role in their scene — a presentation convenience, not authentication. Each speaker can follow this script on their own phone (Presenter Mode → Phone script); it never appears on the projector.
- Every gate is a real form: severity, indicators, amounts, conditions, change ticket, checklist, residual risk. **Do it for me** on the console fills the form on the projector for the audience to see, then signs it; the next person receives it with a deadline.
- Keys in the console: → / Space next · ← back · P pause · Q questions · B next spotlight · M silence NOVA (on the projector too).
- On the end card, → opens questions and → again returns to the card — a stray clicker press never discards the run. “Start again” needs a second click.
- During questions, **Challenge the controls** lets the professor pick a what-if (CEO unavailable, CEO sends it back, the executor or the requester tries to approve). The engine answers on a private copy; nothing is written to the ledger.

## The final step: power off for re-imaging

The story: FIN-WS-07 was **isolated first**, so its memory evidence survived. After verification and closure, the last follow-up powers it off for forensic imaging and re-imaging. For the demonstration, **Karan’s MacBook stands in for FIN-WS-07**. Nothing ever happens automatically: Pavan can only request it, and only Karan’s click on his own Mac authorizes it.

On the public link it is simulated: the projector ends on a black “Powered off by its owner” screen. For the real one:

1. On Karan’s Mac, in the project folder: `npm run dev`, then open `http://localhost:5173/present` → **Open audience window + console** (the real request can only reach the Mac from a copy running on that Mac).
2. In a second Terminal: `npm run remote:preview` for rehearsals (the projector then shows the ending in preview mode, the Mac stays on); `npm run remote:live` only for the real demonstration (or the installed login agent). Save your work first — a confirmed live request powers the Mac off.
3. Both laptops on the same private Wi-Fi. Guest or campus networks with client isolation block pairing: test the classroom network beforehand, or use a phone hotspot.
4. Scene “The last follow-up, on a real device”: Karan opens the 5-minute code from **Final step** on his own screen (main window, not the projector). The projector only shows the pairing status — never the code, the link or the fingerprint.
5. Pavan opens the controller link on Windows (Edge or Chrome), checks the certificate fingerprint with Karan in person, enters the code, then sends the request.
6. The Mac shows its own approval window — Reject is the default. Suggested beat: **reject the first request** (“the Mac stays on — that’s the point”), then authorize the second. The Mac shuts down and the show ends on a dark screen.
7. **Questions:** the console reminds you before the final scene — take questions with evidence on screen *before* it; after the power-off, answer from the phone script (every answer is in it, with who answers).
8. If pairing fails on the day, use **Mac rehearsal** in the console: the same steps, simulated and labelled, ending on the same power-off screen.
